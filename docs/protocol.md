# Протокол капсулы

Капсула — XIAO nRF52840 Sense с магнитометрами. Этот файл описывает обмен с телефоном. Тот же формат записан в коде:
- в прошивке: `firmware/telehaptic/protocol.h`;
- в приложении и в анализе: в их разборщиках пакетов.

Если меняете формат, меняйте все места сразу и повышайте `PKT_VERSION`.

## BLE-сервис

| Что | UUID | Свойства |
|---|---|---|
| Сервис | `7e1a0001-5c2d-4b8e-9f3a-1d6c2b8e4a10` | анонсируется, приложение ищет капсулу по нему |
| DATA | `7e1a0002-5c2d-4b8e-9f3a-1d6c2b8e4a10` | notify, двоичные пакеты с отсчётами |
| CTRL | `7e1a0003-5c2d-4b8e-9f3a-1d6c2b8e4a10` | write / write without response, команды |
| INFO | `7e1a0004-5c2d-4b8e-9f3a-1d6c2b8e4a10` | notify + read, текстовые строки UTF-8 |

- Имя устройства: `Telehaptic`.
- MTU до 247, то есть до 244 байт полезных данных в уведомлении.
- Интервал соединения капсула просит 7,5–15 мс.
- Когда телефон подписывается на INFO, капсула сама присылает полный статус. Он описан ниже.

## Пакет DATA

Порядок байт little-endian.

| Смещение | Поле | Тип | Смысл |
|---|---|---|---|
| 0 | version | u8 | 1 |
| 1 | layout | u8 | биты 0–1: число магнитометров n (0–3); бит 2: IMU есть |
| 2 | packet_seq | u16 | +1 на каждый пакет |
| 4 | first_index | u32 | номер первого отсчёта в пакете |
| 8 | отсчёты | | k штук по S = 18 + 6n байт |

**Номера отсчётов идут подряд с момента включения.** Разрыв в номерах означает потерю. Поэтому приложение считает потери с точностью до отсчёта, и счётчик пакетов для этого не нужен.

Отсчёт:

| Смещение | Поле | Тип | Смысл |
|---|---|---|---|
| 0 | t | u32 | часы XIAO, тики 1/32768 с (RTC2 от кварца 32,768 кГц). Переполнение через ~36 ч |
| 4 | flags | u16 | см. ниже |
| 6 | mag[i].x, y, z | i16 × 3n | сырые единицы чипа; мкТл = значение × 100 / LSB_на_Гс (из строки CFG) |
| 6+6n | gyr x, y, z | i16 × 3 | сырые; мдпс = значение × 17,5 |
| 12+6n | acc x, y, z | i16 × 3 | сырые; мg = значение × 0,244 |

Если IMU нет, на его месте стоят нули.

Сколько отсчётов помещается в пакет: (244 − 8) / S. При n = 2 это 7, при n = 3 — 6.

Пакет уходит, как только он полон, но не позже чем через 30 мс после первого отсчёта. Поэтому на 100 Гц в пакете обычно 3–4 отсчёта.

Флаги `flags`:

| Бит | Смысл |
|---|---|
| 3i + a | магнитометр i (0–2), ось a (0 = x, 1 = y, 2 = z) в насыщении: у QMC5883P \|значение\| ≥ 30000, у QMC5883L ≥ 32767 |
| 9 | мотор включён |
| 10 | у какого-то магнитометра выставлен бит переполнения OVFL/OVL |
| 11 | у какого-то магнитометра нет новых данных (DRDY = 0), значение повторное |
| 12 | с этого отсчёта действуют новые настройки (частота, диапазон, усреднение, пересканирование) |
| 13 | ошибка чтения I2C: значения этого датчика повторяют последние удачные |

Порядок магнитометров: сначала датчик на основной шине, если он есть, затем по номеру канала мультиплексора. Какой датчик на каком канале, видно из строк `SCAN` и `CFG`.

## Команды CTRL

Первый байт — код команды, дальше аргументы, little-endian.

| Код | Команда | Аргументы | Ответ в INFO |
|---|---|---|---|
| 0x01 | частота опроса | u16 Гц: 50 / 100 / 200 | `CFG …` или `ERR …` |
| 0x02 | диапазон | u8 Гс: 30 / 12 / 8 / 2 (у QMC5883L только 8 / 2) | `CFG …` |
| 0x03 | усреднение | u8 a, u8 b. P: OSR1 = a, OSR2 = b (1/2/4/8). L: OSR = 64·a | `CFG …` |
| 0x10 | импульс мотора | u16 мс (1–2000) | `MOTOR on …`, потом `MOTOR off …` |
| 0x20 | пересканировать шину | — | строки `SCAN …`, `CFG …` |
| 0x21 | полный статус | — | см. «Статус» |
| 0x30 | пинг | u32 метка телефона | `PONG <метка> <t>` |

## Строки INFO

Строки идут в USB Serial (115200) и, если телефон подписан, в INFO. Формат: «СЛОВО ключ=значение …».

```
FW 0.1.17
SCAN begin mux=yes
SCAN ch0 0x2C QMC5883P mag1
SCAN ch1 0x2C QMC5883P mag2
SCAN ch2 EMPTY HINT_PULLUPS
SCAN end mags=2
IMU ok LSM6DS3TR-C
CFG rate=100 range=30 osr=8/8 n=2 imu=1 mag1=QMC5883P@ch0,1000 mag2=QMC5883P@ch1,1000
IMU acc_mg_per_lsb=0.244 gyr_mdps_per_lsb=17.5 odr=208
BAT mv=3987
STATS uptime_s=120 samples=12000 overruns=0 dropped=0 imu_err=0 i2c_err=0,0
MOTOR on idx=5012 t=1642291 ms=40
MOTOR off idx=5016 t=1643602
PONG 123456 1650000
```

Что означают строки:
- `SCAN <где> …`:
  - `<где>` — это `main` (основная шина) или `chN` (канал мультиплексора).
  - Варианты: адрес и чип, `UNSUPPORTED`, `UNKNOWN`, `OTHER <адреса>`, `EMPTY HINT_PULLUPS`, `MUX_ERROR`.
  - `HINT_PULLUPS` пишется для пустых каналов 0–2. Приложение показывает его так: «на канале N датчик не отвечает: проверьте провода и подтяжки 4,7 кОм к 3,3 В».
- В `CFG` у каждого магнитометра после чипа и места стоит число LSB на гаусс.
- `MOTOR … idx` — номер отсчёта, `t` — часы XIAO в момент команды или выключения.
- `PONG <метка> <t>` — t снят в момент обработки пинга.
- `BAT mv` приходит раз в 5 с. Способ измерения описан в комментариях `telehaptic.ino`.
- `STATS` содержит счётчики:
  - `overruns` — сколько раз опрос отстал на целый период;
  - `dropped` — пакеты, которые не ушли в радио;
  - `i2c_err` — ошибки чтения по каждому магнитометру.
- Статус — это `FW`, все строки `SCAN` последнего скана, `CFG`, `IMU`, `BAT`, `STATS`.

## Настройки по умолчанию и почему

- QMC5883P работает в режиме Normal, ODR 200 Гц, OSR1 = 8, OSR2 = 8. Это пример из даташита (§7).
- Опрос идёт на 100 Гц, так каждый прочитанный отсчёт свежее 5 мс.
- Диапазон ±30 Гс, 0,1 мкТл на единицу. Обоснование в плане: магнит 8×2 рядом с датчиком может дать больше 800 мкТл.
- QMC5883L работает в режиме Continuous, ODR 200 Гц, OSR 512, ±8 Гс. У этого чипа ±8 Гс — максимальный диапазон.
- IMU: ±8 g, ±500 °/с, ODR 208 Гц.
